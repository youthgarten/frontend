# ADR 0006: 팀원의 맵 위에 쌓고, 맵과 화면은 이벤트 목록으로만 주고받는다

- 상태: 적용 (추가한 이벤트는 팀원과 합의 필요)
- 날짜: 2026-11-20 (같은 날 실제 맵이 올라와 고쳐 썼다)

## 배경

맵과 구역 구성은 다른 팀원이 맡고 있다. 그 팀원의 코드가 다음을 먼저 정했다.

- 폴더를 `src/game/`(Phaser)과 `src/ui/`(React)로 나눈다.
- 둘은 `src/events.ts`의 이벤트 목록으로만 주고받는다. "새 이벤트는 여기에 먼저 추가하고 두 담당자가 합의한 뒤 양쪽에서 쓴다."
- 게임 크기는 1440x900이고, 상호작용 키는 `F`와 `Space`다.

작업은 두 번에 걸쳐 그 팀원의 브랜치 위에 올라갔다.

1. PoC를 만들 때는 PR #1(`feat/classroom-demo`, 회색 상자 교실)이 전부였다. 걸어 다닐 곳이 필요해 임시 광장을 따로 만들었다.
2. PoC를 확인받은 직후 `feat/world-map`에 실제 맵이 올라왔다. 광장(`World`)과 건물 안(`Room`) 두 장면이고, 코드에 "캐릭터 그림 담당자가 교체할 자리", "화면 담당이 실제 패널로 바꿀 자리"가 표시돼 있었다.

## 결정

1. **`feat/world-map` 위에 쌓는다.** 임시 광장은 버렸다. 실제 맵이 있는데 임시 맵을 PR에 넣으면 같은 일을 하는 코드가 둘이 되고, 합칠 때 `App.tsx`, `events.ts`, `PhaserGame.tsx`가 충돌한다.
2. **맵의 배치, 충돌, 장면 전환, 안내 문구는 건드리지 않는다.** 팀원이 표시해 둔 두 자리만 채운다.

| 팀원이 남긴 자리 | 채운 것 |
|---|---|
| `player.ts`의 동그라미 | 픽셀 키트 캐릭터, 걷기와 숨쉬기 동작, 이름표, 레벨별 모자 |
| `PanelPlaceholder.tsx` | 강의 창(`LectureOverlay`)과 시험 흐름(`ExamFlow`). 빈 틀 파일은 지웠다 |

3. **팀원의 이벤트 세 개를 그대로 쓴다.**

| 이벤트 | 방향 | 화면이 쓰는 곳 |
|---|---|---|
| `interact` (`lectures`, `exam`) | 맵 → 화면 | 강의 창과 시험 흐름을 연다 |
| `ui-modal` | 화면 → 맵 | 창이 떠 있는 동안 캐릭터를 멈춘다. 창 부품(`Dialog`)이 스스로 보낸다 |
| `goto` (`plaza`, `classroom`, `exam`) | 화면 → 맵 | "지금 할 일"의 이동 버튼, 수강 완료 뒤 "시험장으로 이동" |

PoC에서 제안했던 길 안내 이벤트(`guide-to`, 캐릭터가 걸어감)는 버리고 팀원의 `goto`(그 공간으로 바로 감)로 바꿨다. 건물 안이 별도 장면이라 걸어서 데려갈 수 없다.

4. **이벤트 네 개와 함수 하나를 추가로 제안한다.** `events.ts`에 "제안"이라고 표시해 두었다.

| 추가한 것 | 방향 | 뜻 | 필요한 이유 |
|---|---|---|---|
| `player-level` | 화면 → 맵 | 내 레벨이 바뀌었다 | 레벨업 연출 뒤 맵의 모자 색을 바꾼다 |
| `place` | 맵 → 화면 | 캐릭터가 있는 공간이 바뀌었다 | 이미 그 건물 안이면 이동 버튼 대신 "칠판 앞에서 F"를 안내한다 |
| `map-connection` | 맵 → 화면 | 멀티플레이 연결 상태 | 끊김과 "다른 곳에서 접속했어요"(종료 코드 4409)를 화면이 안내한다 |
| `map-population` | 맵 → 화면 | 광장에 함께 있는 접속자 수 | HUD에 표시한다 |
| `current(이벤트)` | 함수 | 가장 최근에 보낸 값 | 장면은 화면보다 늦게, 그리고 건물을 드나들 때마다 새로 만들어진다. 그 전에 지나간 `ui-modal`을 놓치면 창 뒤에서 캐릭터가 움직인다 |

5. **내 캐릭터 정보는 이벤트가 아니라 `PhaserGame`의 인자(`profile`)로 넘긴다.** 게임을 만드는 시점에 반드시 필요한 값이다.
6. **멀티플레이 연결은 장면이 아니라 게임이 가진다.** 건물에 들어가면 광장 장면이 끝나지만, 명세는 맵 화면에 있는 동안 연결을 유지하라고 한다. 연결과 다른 접속자의 상태를 게임 단위로 보관하고, 광장 장면은 그것을 그리기만 한다. 건물 안에 있는 사람은 다른 사람에게 문 앞에 서 있는 것으로 보인다.

## 기획서와 달라진 곳

기획서는 "건물 안으로 들어가지 않고 화면 전환도 없다"고 적는다. 실제 맵은 강의실과 시험장을 건물 안 화면으로 나눴다. 맵 담당의 결정이므로 그대로 따랐고, 화면은 어느 쪽이든 동작한다(이벤트만 맞으면 된다). 기획서를 고칠지는 팀이 정한다.

맵의 이름표는 "강의실"이고 기획서와 화면의 말은 "강의장"이었다. 2026-11-20의 새 API 명세가 "강의실"로 쓰므로 2026-11-21에 화면의 말도 "강의실"로 맞췄다.

## 결과

- 이 작업의 PR은 `feat/world-map`을 바탕으로 올린다. `feat/world-map`이 `main`에 합쳐지면 바탕을 `main`으로 바꾼다. `feat/world-map`이 다시 쓰여(rebase) 올라오면 이 브랜치도 다시 맞춰야 한다.
- 팀원의 파일 중 고친 것은 `player.ts`, `World.ts`, `Room.ts`, `PhaserGame.tsx`, `events.ts`, `App.tsx`다. 무엇을 왜 고쳤는지는 PR 본문에 적는다.
- 키트는 팀원이 둔 자리(`src/game/pixel-kit/`)를 쓴다. PoC에서 따로 복사했던 것은 지웠다 ([ADR 0002](0002-vendor-pixel-kit.md)).
