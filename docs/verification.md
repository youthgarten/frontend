# 검증 결과

2026-11-20에 팀원의 실제 맵 위로 옮긴 뒤, 그리고 같은 날 통신 코드를 공통 API 모듈로 다시 짠 뒤 직접 확인한 것과 확인하지 못한 것을 적는다. 아래 숫자와 브라우저 흐름은 모두 API 모듈을 바꾼 뒤에 다시 돌린 결과다. 서브에이전트가 보고한 숫자는 그대로 옮기지 않고, 합친 상태에서 명령을 다시 돌려 얻은 숫자만 적었다.

## 명령으로 확인한 것

| 무엇을 | 명령 | 결과 |
|---|---|---|
| 화면과 모의 서버의 타입 | `npm run typecheck` | 오류 0건 |
| 단위 테스트 | `npm test` | 통과 228건, 실패 0건, 건너뜀 0건 (`main`을 합친 뒤. 배우는 쪽의 테스트 47건이 더해졌다) |
| 빌드 | `npm run build` (타입 검사를 포함한다) | 통과. 묶음 하나가 약 2.10MB(압축하면 약 515KB)이고 크기 경고가 나온다. 대부분 Phaser다 |
| 모의 서버의 흐름 | 서버를 띄운 뒤 `npm run mock:smoke -- http://localhost:5173` | 통과 120건, 실패 0건. 건너뛴 검사는 없다 (스크립트에 건너뛰는 경로가 없다) |

단위 테스트는 틀리면 사용자가 손해를 보는 곳에 붙였다.

| 대상 | 확인하는 것 |
|---|---|
| 시청 구간 측정 (`watchTracker`) | 이어 본 구간, 건너뛰기, 되감기, 나눠 보고할 때의 틈, 영상 길이 넘김, 보고 실패 뒤 다시 보내기, 한 번에 20개 제한 |
| 통신 코드 (`client`) | 토큰 붙이기, 에러 해석, 만료 시 재발급 뒤 한 번 다시 보내기, **동시에 만료를 받아도 재발급은 한 번**, 재발급 실패 시 로그인 풀림 알림 |
| 범용 HTTP 클라이언트 (`core/createClient`) | 주소 만들기, **조회만 다시 시도하고 제출은 다시 보내지 않기**, 시간 제한, 끊기, 훅 |
| 조회의 약속 (`domains/lectures`, `tasks`, `attempts`) | 강의 수강률이나 응시가 바뀌면 어떤 조회가 낡는가, 채점 중일 때만 2초마다 다시 묻기, 채점이 끝난 결과를 처음 받았을 때 한 번만 알리기 |
| 통과하지 못한 이유 찾기 (`ui/exam/passing`) | 두 영역 모두 충족, 영역 점수 미달, 필수 요건 미충족, 검증 최소 점수만 미달, 여러 이유가 겹침, 예전 기준, 채점 전 |
| 자료 그리기 (`ui/exam/Markdown`) | 지원하는 문법, **`<script>` 같은 내용이 실행 가능한 모양으로 나오지 않는 것**, 어긋난 입력 |
| 시간 표시와 남은 시간 계산 (`ui/exam/util`, `useCountdown`) | 경계값, 서버가 준 남은 초와 단조 시계만 쓰는 것 |
| 모의 채점 (`mock/grader`) | 명세 9절의 판정 식, 결과 검사, 다섯 과제의 실제 채점, 시드 계정의 레벨 |

`mock/smoke.mjs`는 실행 중인 서버에 실제 HTTP와 WebSocket으로 요청을 보낸다. 가입과 중복 아이디, 로그인과 쿠키, 재발급과 이전 토큰 폐기, 만료된 토큰, 강의 대시보드, 시청 기록의 조작 방지 한도, 필수 강의 미수강 403, 시험 시작과 중복 시작 409, AI 대화, 답안 저장, 제출과 채점 대기, 레벨 상승, 지난 결과, 포기하기, 재채점, 자동 제출, WebSocket의 인증 실패(4401)·첫 상태 전달·중복 접속(4409)을 확인한다. **실행하면 모의 서버의 데이터가 초기화된다.**

이 스크립트는 맵의 크기와 시작 위치를 `src/game/mapSpec.ts`에서 읽는다. 값을 못 찾으면 검사를 건너뛰지 않고 멈춘다. 처음에는 값이 스크립트에 따로 적혀 있어서, 실제 맵으로 옮긴 직후 2건이 실패했다 (서버는 옳고 검사의 기대값이 낡았다).

## 브라우저로 직접 밟아 본 것

Chrome을 자동으로 조작해 1440x900 화면에서 밟았다. 실제 맵으로 옮긴 뒤 한 바퀴를 두 번, 상태별 흐름을 한 번 끝까지 갔다.

### 한 바퀴 (새로 가입한 계정)

| 단계 | 확인한 것 |
|---|---|
| 회원가입 | 규칙을 어긴 값을 넣으면 칸마다 이유가 뜬다. 가입하면 로그인 화면으로 돌아가고 아이디가 채워져 있다 |
| 로그인 | 틀린 비밀번호에 서버의 안내 문장이 뜬다. 맞으면 광장에 들어간다 |
| 첫 입장 안내 | 세 장을 넘기고 시작한다. 새로고침해도 로그인이 유지되고 안내가 다시 뜨지 않는다 |
| 광장 | 방향키로 걷는다. 내 캐릭터와 가상 접속자 다섯 명이 키트의 그림과 이름표로 보인다 |
| 강의실 | "강의실로 이동"을 누르면 강의실 안으로 간다. 건물 안에서는 이동 버튼이 숨는다. 칠판 앞에서 `F`로 강의 대시보드가 열린다 |
| 강의 | 영상이 없는 강의를 12초 재생하면 시청 기록이 서버에 보고된다. 유튜브 강의는 재생기가 한 개만 뜬다 |
| 시험장 | "시험장으로 이동" 뒤 접수 책상 앞에서 `Space`로 시험관 메뉴가 열린다. 과제 목록에서 강의를 안 들은 과제는 막혀 있다 |
| 시험 | 질문 두 번에 답이 온다. 답안을 쓰고 멈추면 저장 시각이 표시된다. `Esc`를 눌러도 시험 화면이 닫히지 않는다 |
| 행동 기록 | 창 이탈과 복귀를 일으키면 기록 요청이 2건 나간다 |
| AI 실패 | 질문이 입력란에 남고 "다시 시도"가 보인다 |
| 잠시 나가기와 이어 풀기 | 다시 말을 걸면 "이어 풀기"가 나온다. 답안과 대화가 복원된다. 남은 시간이 4분 아래면 타이머의 색과 문구가 바뀐다 |
| 제출과 채점 | 확인 창을 거쳐 제출하고 채점 대기 뒤 결과가 나온다 |
| 결과와 레벨업 | 통과와 레벨 예고가 보인다. 맵으로 돌아오면 레벨업 연출이 나오고 내 정보 카드가 Lv.2로 바뀐다 |
| 지난 결과 | 방금 본 시험이 목록에 있다 |
| 광장으로 나가기 | 건물에서 나와도 초록 모자가 유지되고 다른 접속자가 다시 보인다 |

### 새 채점 방식의 화면 (2026-11-20의 새 명세)

서브에이전트가 1440x900과 1280x720에서 찍은 화면 가운데 과제 안내, 과제 목록, 통과하지 못한 결과(검증 최소 점수 미달)의 두 장을 직접 열어 보았다.

| 화면 | 확인한 것 |
|---|---|
| 과제 안내 | 두 영역을 모두 충족해야 통과라는 기준, 꼭 지켜야 할 것, 영역별 항목과 배점이 응답의 값으로 보인다 |
| 과제 목록 | 통과, 아직 통과 못 함, 잠김의 꼬리표와 최고 총점이 따로 보인다. 잠긴 과제에 "강의실로 이동"이 있다 |
| 통과하지 못한 결과 | 총점 91점인 응시에서 "답변 검증 점수가 최소 점수보다 1점 모자라요"가 총점보다 앞에 나온다. 두 영역의 점수, 최소 점수, 충족 여부가 보인다 |

영역 점수 미달, 필수 요건 미충족, 여러 이유가 겹친 결과, 예전 기준의 통과와 미달, 시험 중 평가 기준 탭은 서브에이전트가 찍어 확인했다고 보고했고, 직접 열어 보지는 않았다. 판정 자체는 단위 테스트와 흐름 확인 스크립트가 확인한다.

## 화면을 보고 고친 것

| 본 것 | 고친 것 |
|---|---|
| 화면의 이동 버튼을 눌러도 건물에 들어가지지 않았다 (개발 모드, 그리고 다시 로그인한 뒤) | 게임이 부서질 때 맵의 `goto` 구독이 남아 부서진 장면이 이벤트를 받고 예외가 났다. 장면 두 곳에서 게임이 부서질 때도 구독을 끊게 했다 |
| 맵의 안내 문구("F 또는 Space: …")가 화면 아래 가운데에 뜨는데 조작 키 안내와 겹쳤다 | 조작 키 안내를 왼쪽 위로, 연결 상태 안내를 위쪽 가운데로 옮겼다 |
| 이름표가 캐릭터와 같은 2배로 커져 옆 사람의 얼굴을 가렸다 | 이름표는 1.5배까지만 키운다 |
| AI 시험관을 접수 책상 바로 뒤에 세우니 말을 걸러 온 내 캐릭터에 가려졌다 | 책상 옆으로 옮겼다 |
| 가상 접속자가 분수 안에 서 있었다 | 가상 접속자가 다니는 범위를 분수 위쪽 돌바닥으로 줄였다 |
| (PoC 때) 창이 열릴 때 창 전체에 파란 초점 테두리가 보였다 | 전역 초점 규칙을 부품이 끌 수 있는 층으로 내렸다 |
| (PoC 때) 창을 겹치면 `Esc` 한 번에 둘 다 닫혔다 | 맨 위 창만 키를 받게 했다 |

## 확인하지 못한 것

| 무엇을 | 왜 |
|---|---|
| 유튜브 영상을 끝까지 재생하며 시청 구간을 보고하는 흐름 | 재생기가 뜨는 것까지만 확인했다. 화면 없이 도는 브라우저에서는 영상 재생이 믿을 만하지 않다. 측정 코드 자체는 단위 테스트와 흉내 재생기로 확인했다 |
| 한글 입력 조합 중 `Enter`가 전송으로 처리되지 않는지 | 코드에 처리가 있는 것은 확인했다. 자동 조작으로는 한글 조합 입력을 재현하지 못한다. 사람이 직접 쳐 봐야 한다 |
| 키보드만으로 모든 화면을 다니는 흐름, 화면 낭독기로 읽기 | 하지 않았다 |
| 1280px보다 좁은 화면 전체 | 1280px 미만에서는 시험 화면이 탭으로 한 영역만 보인다. 자료와 답안을 함께 볼 수 없다. 고치지 않았다 |
| 화면 낭독기로 직접 읽어 보기 | 하지 않았다. 낭독기에 전달되는 글자와 속성이 있는지만 확인했다 |
| 제출 클릭과 시간 종료의 자동 제출이 실제로 겹치는 경우 | 재현하지 못했다. 겹쳤을 때 서버가 주는 409를 "이미 제출됨"으로 받는 코드는 있다 |
| 실제 백엔드와의 연결 | 백엔드가 없다 |
| 실제 화면 주사율에서의 캐릭터 이동 속도와 키 반응 | 화면 없이 도는 브라우저는 초당 약 20장으로 그린다. 이때 아주 짧게 누른 키는 맵이 놓쳤다 (한 장면이 그려지는 사이에 누르고 뗀 경우). 팀원의 원래 코드도 같은 방식이고, 초당 60장으로 그리는 실제 화면에서 사람이 누르는 길이로는 생기지 않을 것으로 보이나 직접 봐야 한다 |
